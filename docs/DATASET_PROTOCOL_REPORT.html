1. 执行摘要

本报告记录 SACM-Plus 当前实验所使用的数据组织方式、划分规则、审计结果和设计取舍。 核心结论是：数据源池可以安全用于后续实验；训练/验证/测试 split 由我们自己固定，并非官方 SACM 的原始 split。

当前协议 v1（已生成并冻结）
6 个 Seen 域 × 3-shot = 18 张训练图；每域 1 张验证图，共 6 张（CORN 用官方 val）； 5 个原有 Seen 域的留出部分 493 张 + CORN 官方 test 152 张 = 645 张 Seen test； 7 个 Unseen 数据集共 1,640 张；4 个 Novel 数据集共 147 张（新增官方 LEAF 31 张）。
v1 修订（2026-10-23）
CORN 与 LEAF 由论文作者提供，已按 SACM 官方实验配置接入： CORN 成为第 6 个 3-shot 训练域，其官方 batch-disjoint test 进入 Seen； LEAF 恢复为 Novel 第 4 个数据集。早期 v0 已删除；当前只保留 data/sacm_3shot。
仍不是官方 SACM 的严格复现。 v1 已对齐官方训练预算（6 域 × 3-shot = 18 张）和 Novel 组成（ROAD/LEAF/TYRE/WIRE = 147 张）， 但官方没有公开具体的 3-shot 样本 ID，且 Seen/Unseen 组成仍受 DSCA 权限、官方 CRACK split、 DRIVE 官方 test 无血管 GT 等限制。官方数字仍只能作为参考；正式主表必须在 v1 split 上重跑 SACM 和 baseline。

2. 数据组织流程

① 原始数据18 个原始目录，格式各异
② 标准源池统一 images / masks / manifest
③ 实验 splittrain / val / seen test
④ 外部测试unseen / novel 整块测试

目录分工：

  • segment/datasets/：原始数据仓库，保持原始格式；
  • sacm_plus/datasets/：统一格式的标准源池，每个数据集包含 images/、masks/、可选 fov/、manifest.csv；
  • sacm_plus/data/sacm_3shot/：当前论文实际使用的固定 split；
  • docs/DATASET_PROTOCOL_REPORT.html：本报告。

20 个源池全部通过独立脚本生成，例如 scripts/datasets/prepare_DRIVE.py、 scripts/datasets/prepare_OCTA-500.py。源池不会被训练脚本直接修改； 训练/测试只读取固定的 split 或外部测试源池。

4.2 CHASEDB1 为什么有 2 张未使用

CHASEDB1 有 14 位患者、每人左右眼各一张，共 28 张，且没有官方 train/test split。 当前 split 使用患者级分组：

  • Train 3 张来自患者 02 和 06；
  • Val 1 张来自患者 10；
  • Seen test 使用其余 11 位患者的 22 张；
  • Image_02R 和 Image_10R 未使用。

未使用的两张如果放入 Seen test，会让患者 02/10 同时出现在 train/val 和 test，造成患者级泄漏； 如果放入 train/val，又会超过 3-shot / 1-val 配额。因此这是患者级隔离的必然结果，不是漏图。

备选方案是常见的 20/8 划分（后 4 位患者测试）。本协议没有采用，因为官方具体 8 张测试图未公开， 20/8 会留下 16 张训练池图不用，且不能解决官方 3-shot ID 未知的问题。

4.3 CREMI 为什么有 246 张未使用

CREMI 当前按 volume 隔离：Train 来自 B volume，Val 来自 A volume，Seen test 只用 C volume。

  • A/B 共 250 张；train/val 使用 4 张，剩余 246 张；
  • C 共 123 张，全部作为 Seen test；
  • A/B 剩余图不能进 Seen test，否则测试与训练共享 volume，造成泄漏；
  • 3-shot 配额固定，也不能把它们全部加入 train/val。

备选：A 训练/验证，B+C 测试，可把 Seen test 从 123 提升到 248，未使用降到 121； 但训练只来自一个 volume。本 v1 保留 A/B 训练、C 测试的 leave-one-volume-out 方案。

4.4 Image-level 划分的风险

DRIVE、DCA1、CrackTree200 的源池没有可用的患者/病灶分组元数据，v1 采用 image-level 划分。 如果原始数据集实际存在同一患者多张图，可能产生弱患者级泄漏；论文中必须明确说明这一点。 后续 v2 应优先检查这些数据集的 patient/session 元数据。

8. 设计决策与取舍

8.1 为什么 v1 恢复为官方 6 个 Seen 域

官方 SACM 使用 DRIVE、CHASEDB1、DCA1、CrackTree、CREMI、CORN 六个训练域， 共 18 张 3-shot 图。v0 因当时没有 CORN 而使用 5 个域、15 张图； 2026-10-23 作者提供了 CORN-1 的官方 batch-disjoint split，v1 已恢复 6 域、18 张， 并把官方 test 152 张纳入 Seen。

  • 官方没有公开 3-shot 样本 ID，v1 用 seed 42 固定采样，仍不能逐位复现；
  • CORN 的 3 张训练图来自 3 个不同 batch（7/3/6），val 用官方 batch 9；
  • 早期 v0 已删除；所有新实验以 sacm_3shot 为准。

8.2 为什么 CHASEDB1 用 3 / 1 / 22

CHASEDB1 没有官方 split。当前方案使用患者级分组，3 train、1 val、22 test； 2 张未使用是患者左右眼无法安全拆分的必然结果。 该方案比常见 20/8 使用更多测试图，同时保持患者隔离。

8.3 为什么 CREMI 保留 A/B 训练、C 测试

这是一个干净的 leave-one-volume-out 设计：Seen test 只使用 C volume， 不与 train/val 的 A/B 共享 volume。代价是 A/B 剩余 246 张被闲置， 但这比把训练 volume 放进测试更安全。

8.4 为什么候选数据集不进入主表

  • OCTA-500 本地只有 300 个 projection，不是完整 500；
  • TopoMortar 前景比例偏高，适合单独分析；
  • DeepGlobe 有 6,226 对，数量会主导 Unseen 平均；且角色尚未最终确认。

8.5 为什么 v1 恢复 LEAF（附标注 caveat）

LEAF 是 SACM 官方 Novel 集的一部分，v1 使用论文作者提供的 31 张官方数据， 以保持 Novel 组成与论文一致（ROAD/LEAF/TYRE/WIRE = 147）。 其 mask 确实存在大量 1 像素断点（中位数 305 个 8-连通分量，39% 分量 ≤4 px）， 这是官方标注本身的属性：主表仍使用官方 mask，但拓扑指标（clDice/HD95/Betti） 需在论文中注明“对标注断点敏感”，不能把它当作干净的拓扑基准。

8.6 为什么 OCTA-500 只有 300 对

本地 OCTA(ILM_OPL) 只有 10001–10300 共 300 个 2D 投影； GT_LargeVessel 有 500 个标签。10301–10500 没有匹配投影， 因此不能配对。这不是脚本截断，是本地原始数据不完整。

10. 评测与 Baseline 计划

10.1 指标

主表建议统一报告：Dice、IoU、clDice、HD95。所有方法使用同一套评测代码。

10.2 聚合方式

每个数据集单独报告，再报告 Seen / Unseen / Novel 的 macro average。 不要用像素数加权，否则 CHCrack5k 这类大数据集会压过 STARE / LES-AV。

10.3 随机性

  • 固定同一份 split；
  • 训练 seed 0、1、2，报告 mean ± std；
  • 不要每个训练 seed 重新抽 3-shot，否则协议会变；
  • 如果研究 shot 采样方差，另做实验，不混入主表。

10.4 Checkpoint 选择

每域只有 1 张 val（共 5 张），early stopping 噪声较大。 建议固定训练 epoch/step budget，或明确写清 checkpoint 选择规则； 绝不使用 Seen/Unseen/Novel test 调参。

10.5 Baseline 重跑

  • 必须重跑：SACM（官方代码 + 当前 split）；
  • 优先重跑：3–5 个有公开代码、能适配 3-shot 的强 baseline；
  • 其余方法：如果代码不可用或成本过高，只放“官方报告值”表，并标注不同协议；
  • 主表只放“our protocol, all methods rerun”的结果；官方数字单独放附录。

12. 限制与发表清单

12.1 必须写进论文的限制

  • CORN 使用作者官方 batch-disjoint split，但 3-shot 具体图片仍是 seed 42 抽样，不是官方 ID；CORN Seen 用 152 张，论文报告 100 张；
  • 官方 3-shot 图片 ID 和完整测试 split 未公开，本协议为自定义 split；
  • CHASEDB1 没有官方 split，采用患者级 3/1/22；
  • CREMI 使用 A/B 训练验证、C 测试，A/B 剩余 246 张未使用；
  • DRIVE、DCA1、CrackTree200 使用 image-level split，可能存在未识别的患者级泄漏；
  • LEAF 官方 mask 细线断点多（中位数 305 个 8-连通分量，39% 分量 ≤4 px），拓扑指标需注明标注 caveat；
  • OCTA-500 本地只有 300 对，TopoMortar / DeepGlobe 尚未进入主协议；
  • 极低前景数据集（CHCrack5k、CrackTree200）的指标对小目标敏感；
  • 官方 SACM/baseline 数字与当前协议不可直接比较。
